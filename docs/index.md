# HiveMind Provider

Manage HiveMind Forager resources with a service account that has the `read` and `manage` scopes. Authenticate with a static service-account token, an OIDC id_token, or (inside GitHub Actions) the runner's OIDC token, which is exchanged at `/v1/auth/actions/exchange` for a short-lived HiveMind token.

Requires Terraform 1.11 or later for write-only secret attributes.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.11.0"
  required_providers {
    hivemind = {
      source = "wandb/hivemind"
    }
  }
}

# Set HIVEMIND_TOKEN to a service-account token with read and manage scopes.
# Set HIVEMIND_ENDPOINT when using a different HiveMind deployment.
provider "hivemind" {}
```

## Authentication

Create a HiveMind service account with `read` and `manage` scopes. Only organization
admins can create accounts with `manage`; personal access tokens cannot carry it.
Set `HIVEMIND_TOKEN` to a token minted for that account. Set `HIVEMIND_ENDPOINT`
when using a deployment other than `https://hivemind.wandb.tools`.
`HIVEMIND_ORG_ID` optionally selects an organization using the `X-Org-Id` header.

In GitHub Actions, grant the job `permissions: id-token: write` and configure the
service account's OIDC selector for that repository. With no static token set,
the provider fetches the runner's OIDC token and exchanges it for a short-lived
HiveMind token. For another supported OIDC issuer, supply `HIVEMIND_OIDC_TOKEN`.
Set only one authentication method.

The `manage` scope covers sandbox secret writes; a separate `write` scope is not required.
Secret names must use 1–64 letters, digits, or underscores and start with a letter or underscore.

## Secrets and state

Use environment variables for provider credentials. Pass resource secrets through
`sensitive = true`, `ephemeral = true` input variables into `headers_wo` or
`value_wo`; those write-only values are excluded from state and saved plans.
Change `headers_wo_version` or `value_wo_version` after rotation so Terraform
sends the new value. Each update to a service integration re-sends its complete
headers; omitting `headers_wo` removes the stored credentials.

Other attributes, including environment scripts and non-secret environment
variables, are stored in state. Use sandbox secrets and `env_secrets` references
for credentials, and protect state and plan files.

### Optional

- `endpoint` (String) HiveMind API URL. Defaults to `$HIVEMIND_ENDPOINT` or `https://hivemind.wandb.tools`.
- `oidc_audience` (String) Audience requested from GitHub Actions. Defaults to the endpoint, matching the HiveMind daemon.
- `oidc_token` (String, Sensitive) OIDC id_token to exchange for a HiveMind token. Defaults to `$HIVEMIND_OIDC_TOKEN`.
- `org_id` (String) Organization to act in (sent as `X-Org-Id`). Defaults to `$HIVEMIND_ORG_ID`; usually unnecessary for service accounts.
- `token` (String, Sensitive) Service-account token. Defaults to `$HIVEMIND_TOKEN`.
